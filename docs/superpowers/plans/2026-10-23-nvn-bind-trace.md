# NVN 绑定序列诊断增量

## 目标

在调整运行时状态结构前，复用现有 `nvnCommandBufferBindProgram` 诊断日志，统计实际阶段掩码与连续绑定模式。仅从日志可确认命令掩码、程序是否为空、阶段数、帧号；不能推断每个程序中的着色器所属阶段，也不能从截取的日志推断整款游戏的覆盖率。

离线模型可按掩码把程序指针与序号登记到六个阶段，指出顶点/片元来源分离或只剩一个阶段的转变。它看不到绘制或派发命令，因此此类转变是待验证的绑定状态，不能直接算作实际画面错误。

## 实施

1. 先写无游戏数据测试，覆盖重复掩码、`0x3` 后空 `0x3c`、仅计算绑定、部分顶点/片元绑定、非法位、畸形记录和同一行多条记录。
2. 增加离线命令 `games/totk/scripts/analyze_nvn_bindings.py LOG`，流式读日志并只向标准输出写 JSON。报告掩码与空/非空次数、连续模式、部分绑定、来源分离、未知位、诊断记录数和行号；不输出原始程序地址或调用链。
3. 用现有恶魔城诊断日志做只读分析，记录汇总和源日志外部位置，不把日志复制到源码目录。
4. 运行目标测试及测试全集，检查工作树无构建产物。此工具完全离线，不进入游戏热路径。

## 下一道门槛

收集王国之泪和卡比的同类日志后，再决定是否可把常见图形/计算双通道分离为默认语义。几何、细分和部分图形绑定须通过单独的程序阶段身份探针；无法证明时保留“不支持”状态。实机画面与冷/热缓存帧时间测试仍是启用新运行时的必要条件。
