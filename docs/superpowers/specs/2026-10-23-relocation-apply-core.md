# 共用重定位写入核心：离线等价与成本验证

## 目标

在已经核对映像哈希与重定位结构的前提下，用共用 C 接口把 `RELR`、`RELA` 和 `PLT RELA` 直接应用到映像的可写数据段。接口只负责地址计算与八字节写入；游戏的符号查找、弱符号和宿主覆盖仍由调用方回调决定。本阶段不切换王国之泪或其他现有游戏的装载器。

## 接口与语义

`mng_reloc_apply` 复用 `mng_reloc_walk` 的源表和目标边界检查。调用方传入映像、已经预检的表布局、映像实际基址和符号解析回调。离线预检本身允许源表位于数据段；流式写入另要求所有源表完整位于 `data_off` 之前，不满足时在任何写入前拒绝，未来调用方需选择旧路径或其他安全回退。相对重定位写入 `base + addend`；`ABS64` 与 `GLOB_DAT` 写入 `symbol + addend`；`JUMP_SLOT` 按当前项目装载器的约定写入 `symbol`。未知类型、无效表、越界目标或解析失败停止处理并返回错误。输入契约要求离线预检已排除重复目标；运行时不为此分配大集合。若错误发生在部分写入之后，调用方必须丢弃已修改映像并重新装载，不能就地重试。

## 验证

合成测试检查四种类型、RELR 隐式加数、解析失败停止以及源表位于可写段时写入前拒绝。真实马里奥本体只在项目外临时目录重新生成已验证映像：用固定的测试符号地址独立构造平铺表基线，与流式写入后整段可写数据的摘要逐模块比较；不得把这些地址当成真实宿主绑定。重复离线计时将读取、解析和写入都计入两条路径，明确它不包含真实服务回调、权限切换、构造器、App 启动或逐帧负载。大型映像与基线数组清理，仅留小型摘要。

## 性能决策

如果流式写入明显增加离线装载成本，记录成本并保留现有路径，之后以真实 App 启动基线决定是否接入。此核心只在装载时运行，不进入逐帧路径。即使离线对拍成功，也不宣称游戏可运行或帧率改善。
