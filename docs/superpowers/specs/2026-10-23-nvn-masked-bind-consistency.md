# NVN 阶段掩码：回放与前瞻的一致性

## 已有证据

恶魔城的命令流先以 `0x3` 绑定顶点与片元程序，随后以空程序和 `0x3c` 清除其他阶段。`CASTLEVANIA_NATIVE_PROBE` 宿主的实际回放已保留图形程序，`CASTLEVANIA_MASKED_BIND=0` 是原有负对照；实机记录和结果见 `games/castlevania/README.md`。此规则目前仍限于该配置，不能据此声称已支持任意阶段组合。

检查 `nvn_mtl.m` 发现，提交前的写回索引、推迟绘制和通道合并扫描直接用记录中的程序覆盖预判状态。这与实际回放不一致：相同的 `0x3c` 空绑定会在扫描中把图形程序清空，使采样与附件依赖判断依据错误。`ds_scan` 只在看到程序时累加保守深度需求，不跟踪当前程序，本次不改变它。

## 本次改动

将“空程序、阶段掩码不包含顶点或片元时保留图形程序”的选择规则提取为无副作用的内联函数。实际回放和所有跟踪图形程序的前瞻扫描调用同一个函数。继续由 `CASTLEVANIA_NATIVE_PROBE` 与 `CASTLEVANIA_MASKED_BIND` 控制，保留现有负对照。函数只在绑定操作出现时执行，不进入逐绘制或逐像素路径，也不改变缓存键与管线编译。

测试用不含游戏数据的 C 探针覆盖：图形绑定后清除 `0x3c`、显式清除顶点或片元、未启用时的旧行为、连续绑定。编译产物放在系统临时目录。全量 Python 测试与源码清洁检查是本轮门槛；GPU 画面和帧时间仍须在项目外的已验证宿主与隔离存档中复验，不能从合成探针推断。

## 后续通用化边界

当前 `S.prog` 同时供绘制和计算派发使用；完整 NVN 阶段语义需要按六个阶段独立记忆绑定，并让绘制、派发和所有前瞻读取相同快照。还要确定部分图形阶段来自不同程序时的着色器组合与管线缓存键。实现前先对三款游戏收集绑定序列，建立含计算切换、部分图形替换、空绑定及跨命令列表的合成和 GPU 探针，再比较冷/热缓存帧时间、长帧、管线创建次数和内存。只有跨游戏通过后才能去除编译分支。
