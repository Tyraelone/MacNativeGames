# 按实际重定位统计模块符号候选

## 目标

把共用静态装载前检查从“能解析重定位表”推进到“按实际符号重定位汇总候选类别”。只根据已核对的 `main/subsdkN/sdk` 表和现有装载器的模块查找顺序计算；不声称宿主覆盖、ABI 兼容或运行成功。`rtld` 按现有约定不参与待装载模块查找。

## 结果

每个待装载模块报告：符号重定位总数、使用本模块强定义的候选数、按模块顺序找到的定义候选数、无模块定义但可置零的弱符号数、无模块定义且必须由宿主提供的强符号数；后两类附去重的符号名。只统计实际被非相对重定位引用的符号，不把未引用的动态导入算成装载阻碍。

按当前装载器规则，本模块非弱定义优先；弱定义需要按 `main → subsdkN → sdk` 的全局查找顺序预占先。每个模块内同名定义使用首个符号，与其哈希表行为一致；超出 `KEY_PAGE_OFF` 的定义不能成为地址候选。宿主覆盖和 `JUMP_SLOT` 观察门可以抢先绑定，所以分类只能称为候选。弱置零也不保证后续调用安全。

## 验证与边界

合成数据覆盖本模块强定义、跨模块候选、弱置零、强宿主需求、未被引用的导入，以及无效定义地址。真实马里奥本体在项目外临时目录重建静态表，汇总实际重定位引用的类别；大型数据清理，仅留下小型摘要。本阶段只改变离线 JSON 报告与文档，不改变游戏装载、服务或渲染路径。
