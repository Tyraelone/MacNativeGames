# 精简运行时模块描述表

## 目标

从已验证的共用装载预检结果生成一份游戏无关的 C 描述表，只编码模块顺序、改写映像哈希、段边界、原始符号/重定位表位置和少量宿主门。它可作为未来直接读取装载器的可选输入，同时保留当前游戏各自的平铺表路径。生成物和验证映像只能放在源码项目外。

## 格式与信任边界

描述表使用源码中的稳定结构定义，不复制动态符号名或重定位记录。构建命令核对每个原始 NSO 和改写映像与预检中的 SHA-256，用原始 NSO 的符号段范围重新解析符号，并拒绝落在可写数据段内的重定位源表；C 消费端仍检查文件大小、布局、表边界、符号名终止、重定位类型和目标、宿主门边界。未来正式装载时还必须在映射后复核映像 SHA-256。描述表不包含特定游戏的构造器状态地址、PLT 诊断插桩或宿主服务实现。

宿主门在生成时按返回地址排序，消费端用单次线性扫描检查顺序、唯一性和参数范围。

## 验证与性能边界

合成数据检查模块顺序、可选 RELR/PLT、门类型和不受信的表/路径。马里奥本体在项目外重建真实预检，用生成头编译 C 探针，逐模块核对描述数据及源表可读性；记录头文件大小及与额外平铺符号/重定位行的大小关系。这里只衡量生成元数据的体积，不推断 App 冷启动、逐帧表现或任何游戏已经可通用构建。
