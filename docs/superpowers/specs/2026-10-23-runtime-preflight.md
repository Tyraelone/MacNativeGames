# 共用静态装载前检查

## 目标与边界

接在已验证 ExeFS 和共用 NSO 改写探针之后，按实际模块集解析原生装载器所需的静态模块数据。`main` 必需，`subsdkN` 可选且按序，`sdk` 可选；`rtld` 按现有原生装载器约定只登记为排除模块。此阶段不生成 App，不调用游戏代码，不证明宿主服务、构造器、NVN 或性能。

## 输入与输出

`python3 game_tools/runtime_preflight.py --exefs EXEFS --manifest MANIFEST --rewrites REWRITTEN --output OUT`。所有输入和新的输出目录必须位于源码目录外。先核对原始 NSO 清单、改写摘要、改写器版本、模块集、各文件哈希和 build ID，再解析动态符号、RELR/RELA 重定位与宿主门；不支持的类型、越界或重复写入一律失败。完整静态数据与小型摘要仅在全部模块通过后原子公布，失败清理本次暂存目录。

## 性能决策

这是离线解析，不改游戏热路径。摘要列出各模块重定位数、原始表字节数和平铺 `Reloc` 表的估算字节数，供下一阶段选择装载器数据结构。先验证是否能直接使用已校验映像内的重定位表，避免另存等量平铺表；是否改善启动时间需在实际 App 中测量，同场景帧时间仍另行 A/B。
